# Diffie-Hellman Key Exchange

## Суть

Diffie–Hellman позволяет двум сторонам получить общий секрет по открытому каналу. Алиса публикует `g^a`, Боб — `g^b`, после чего оба вычисляют `g^(ab)`. Пассивный наблюдатель видит параметры и публичные значения, но для восстановления секрета должен решить связанную задачу дискретного логарифма.

## Как устроено

- Долговременные или эфемерные секреты выбираются случайно в допустимом диапазоне подгруппы.
- Полученное групповое значение служит основой общего сеансового ключа по правилам выбранного протокола.
- Эфемерные ключи могут обеспечить forward secrecy относительно последующей компрометации долгоживущего ключа.
- Проверка параметров и public value предотвращает малые подгруппы и некорректные элементы.

## Ключевая формула

Стороны публикуют $g^x$ и $g^y$, после чего независимо получают один секрет: $$K_A=(g^y)^x=g^{xy}=(g^x)^y=K_B.$$

<!-- reviewed-notation:start -->
**Обозначения и условия.** G — конечная циклическая группа порядка q, g — её образующий; x,y — секретные скаляры 1…q−1. Все степени и произведения вычисляются в G (для группы вычетов — по модулю p). K_A,K_B — общий элемент группы, ещё не прикладной ключ: его кодирование и функция выработки ключей задаются протоколом.
<!-- reviewed-notation:end -->

## Практический разбор

<!-- reviewed-example:start -->
*Происхождение:* Составленный учебный пример; не экспериментальный результат курса.

**Исходные данные.** p=23,g=5; Алиса x=6, Боб y=15.

1. Алиса отправляет A=5⁶ mod 23=8; Боб B=5¹⁵ mod 23=19.
2. Алиса вычисляет 19⁶ mod 23=2; Боб 8¹⁵ mod 23=2.

**Результат.** Получен один общий секрет 2.

**Проверка.** 19²≡16,19⁴≡3,19⁶≡3·16≡2. Значение совпадает с модульным расчётом стороны Боба.

**Граница применимости.** Без аутентификации сообщений A/B посредник может согласовать отдельные секреты с каждой стороной. Числа учебные.
<!-- reviewed-example:end -->

### Дополнительное пояснение из конспекта

Сам обмен не аутентифицирует участников. Активный посредник устанавливает независимый секрет с каждой стороной; подпись транскрипта, PSK или сертификат должны связать значения обмена с идентичностями.

## Ограничения и безопасность

- Неаутентифицированный DH уязвим к Man-in-the-Middle.
- Повтор слабого секрета или отсутствие валидации public value снижает стойкость.
- Протокол должен связывать полученный ключ с аутентифицированными сторонами и текущим сеансом.
